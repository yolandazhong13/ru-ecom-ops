================================================================================
ARCHITECTURE NOTES
================================================================================

Deduplication Strategy:
  - Entry ID: SHA-256(order_id + platform + shop_id)[:16]
  - Prevents duplicate entries in ledger
  - Fast lookup by entry_id

State Mapping:
  - WB states: "new", "confirmed", "shipped", "in_transit", "delivered", "completed"
  - Ozon states: "awaiting_payment", "processing", "awaiting_shipment", etc.
  - Both map to unified OrderState enum

Anomaly Classification:
  - Timing: Payment/shipment/delivery delays
  - State Transition: Unexpected cancellation/refusal/return
  - Data Quality: Missing ID, invalid amount, missing SKU
  - Reconciliation: Missing on platform or in ledger

Alert Routing:
  - P0 (immediate): One alert per anomaly, full context
  - P1 (hourly): Batch by shop, type breakdown
  - P2 (daily): Single summary with categories
